# simulation-dji-adapter 二级模块契约

状态：已实现  
所属一级模块：cross-runtime-e2e（验证模块，不属于产品运行时）  
逻辑 Gradle 路径：`:cross-runtime-e2e:simulation-dji-adapter`

## 1. 唯一职责

`simulation-dji-adapter` 的唯一职责是：在普通 Kotlin/JVM 进程中，以**一台可控、可观察且确定性的模拟 DJI 设备**实现手机端现有业务模块所依赖的 DJI/Android 外部端口。

它让 `relay-test-harness` 能在不依赖 Android、DJI MSDK、遥控器、飞机、相机或网络视频源的情况下，装配并驱动真实的：设备连接、遥测、航线上传与执行、飞控、相机/图传设置和 RTMP 控制业务模块。它还为端到端故障注入与固定种子生成式验证提供同一份设备事实来源。

它不是手机中继器，不实现 WebSocket、协议编解码、命令分发、文件分块传输、桌面状态、地图、媒体接收或产品 UI；不得构造或解析任何 Relay 帧，不得直接调用桌面端代码，也不得绕过手机端正式业务模块修改任务、设置或遥测状态。生产 Android 组合根、产品模块和 APK 不得依赖它。

删除本模块后，产品仍可连接真实 DJI 设备；仅失去跨进程验证时的确定性外部设备替身。

## 2. 对外接口

```text
SimulationDjiAdapter.create(plan, clock) -> SimulationDjiAdapter

adapter.ports() -> SimulationDjiPorts
adapter.snapshot() -> SimulationDjiSnapshot
adapter.advanceUntilIdle() -> Unit
adapter.advanceBy(duration) -> Unit
adapter.inject(event) -> SimulationInjectionResult
adapter.close() -> Unit
```

`SimulationDjiPorts` 是仅供 `relay-test-harness` 注入正式手机模块依赖的只读端口包，包含下列现有端口的实现：

```text
DjiSdkPort
RemoteControllerPort
AircraftPort
PairingPort
PairingStatusPort
FlightTelemetrySource
MissionUploadPort
MissionControlPort
MissionExecutionSignalSource
DjiFlightPort
DjiSettingsPort
DjiStreamPort
```

端口包不暴露可变内部集合、定时器、测试脚本或桌面端对象。调用者只能按各正式端口现有契约使用它们；不能通过类型转换取得模拟器私有状态。`ports()` 在关闭前始终返回同一批端口实例，关闭后端口只保留其各自正式契约所允许的安全失败或静默语义。

`SimulationDjiPlan` 是创建时不可变的场景说明，至少包含：

1. 初始设备事实：SDK、遥控器、飞机、配对状态、能力、遥测、相机设置、图传设置和图传状态。
2. 每类外部操作的结果计划：航线上传、开始/暂停/继续/停止航线、起飞/降落/返航、设置读取/写入、开始/停止图传、配对开始/停止、端口注册和释放。
3. 每个结果的交付方式：正常、同步拒绝、异步失败、抛出、超时、不回调、重复回调、迟到回调。
4. 操作成功后应产生的设备事实与可选航线信号；未明确声明时不得凭空推断飞行、航线完成或视频可播放。

`SimulationClock` 由调用者提供，且只允许单调向前推进。模块不得创建真实睡眠、线程、协程延时、随机数或后台定时器。所有计划中的异步结果、设备回调和迟到事件都必须经该时钟排队、推进和交付，因此同一计划与同一动作序列必须得到相同快照和相同观察顺序。

`inject(event)` 只允许端到端验证编排器显式注入外部世界事实，例如：遥控器/飞机连接变化、SDK 失效、遥测变化、DJI 航线原始信号、设置缓存变化、端口释放失败和已安排操作的迟到回调。它返回 `Applied`、`Rejected` 或 `Ignored`；非法注入绝不改变设备事实。它不得接受命令帧、桌面快照、任意 JSON、文件路径或未校验的异常对象。

`snapshot()` 返回一份不可变、脱敏且可比较的 `SimulationDjiSnapshot`。它至少包含设备代次、当前设备事实、当前航线文件名与上传状态、航线控制状态、飞控请求记录、设置快照、图传状态、已排队事件数量和已关闭标记；不包含绝对路径、文件内容、密钥、真实设备标识、原始异常或堆栈。

## 3. 设备事实模型

模拟器内部只维护一份原子设备事实。所有端口从该事实读取，所有有效外部结果先更新事实、再按正式端口回调。任何时刻：

- 遥控器、飞机、SDK、配对和能力是设备连接模块的事实来源；它们不由航线、飞控或设置端口自行伪造。
- 遥测字段只能通过 `FlightTelemetrySource` 的正式快照和订阅路径提供。成功调用起飞、降落或返航只记录“DJI 接受/拒绝该请求”，不自动伪造 `isFlying`、高度、位置或返航完成；这些必须由计划的遥测事实或显式注入给出。
- 航线文件在 `MissionUploadPort` 成功终态前不得成为当前已上传文件。上传接受、上传成功、开始请求接受、进入航线、暂停、恢复、停止、完成、打断和断连是不同事实，必须分别由计划或注入驱动。
- 只有原始航线信号 `FINISHED` 可以经 `MissionExecutionSignalSource` 交付完成；`RETURN_TO_START_POINT`、开始成功回调、上传成功或任意文本都不得伪造完成信号。
- 设置写入成功后，只有计划允许且通过正式读回的完整同域快照才能成为新设置事实。缺字段、跨域字段、非法枚举、非有限数值或不完整读回必须表现为失败，不能用默认值补齐后报告成功。
- 图传开始/停止成功只表示 DJI 图传控制调用的终态；不产生视频帧、不宣称 RTMP 已连接或播放器可用。

每次外部设备失效、重连或 SDK 重启都必须产生新的设备代次。旧代次中尚未交付的端口回调、航线信号和遥测通知到达时，必须被正式端口隔离或被模拟器标记为过期；它们不得污染新代次的事实。

## 4. 操作计划与六类外部结果

每一次端口操作消耗其所属操作队列的一个结果项；队列耗尽时使用该操作类别的明确默认项。默认项必须在计划中给出，禁止隐式成功。

所有外部接缝至少支持并在测试中可配置下列结果：

| 结果 | 语义 |
| --- | --- |
| 正常 | 以计划延迟完成一次成功或业务失败回调，并只更新计划声明的事实。 |
| 拒绝 | 在调用返回前按正式端口的拒绝类型返回，不安排回调，也不改变事实。 |
| 抛出 | 在调用点抛出由端口契约允许的安全异常；不泄露 DJI/Android 类型。 |
| 超时 | 不在业务模块时限前交付终态；业务模块自行超时后，模拟器仍可按计划保留迟到回调。 |
| 重复 | 以同一操作代次安排两次或更多同类终态/事实回调，用于验证上层最多完成一次。 |
| 迟到 | 在取消、关闭、设备代次变更、断线或业务超时之后交付；不得反转已经确定的上层终态。 |

除上表外，计划可表达“异步失败”“不回调”“释放失败”和“回调中抛出”。这些是验证便利，不改变六类必须覆盖结果的含义。重复、迟到、失败和抛出均不得自行中止后续已排定的独立设备事实；是否隔离由真实业务模块的公开端口契约决定。

## 5. 正式端口映射

### 5.1 设备连接与配对

`DjiSdkPort`、`RemoteControllerPort`、`AircraftPort`、`PairingPort` 和 `PairingStatusPort` 共同描述一台同一代次设备。订阅建立、首个事实、变更、取消、重复订阅、注册异常、释放异常、停止、重启、断线和旧回调必须与各端口既有契约一致。

一个连接事件不得部分更新互相矛盾的事实。例如飞机断开后，模拟器不得继续将该代次报告为“飞机已连接且能力可用”；设备能力必须通过既有 `DeviceCapabilityReader` 从正式 `DeviceSnapshot` 计算，而不是由模拟器向网关直接发布。

### 5.2 遥测

`FlightTelemetrySource` 必须提供完整不可变快照、变更订阅、幂等注销和关闭后静默。对每次有效遥测注入，先形成完整的新快照，再在锁外通知；字段合法范围与 `android-flight-telemetry-adapter` 契约一致。无效经纬度必须同时清空经纬度，未知或非法飞行模式必须为 `null`。

### 5.3 航线

`MissionUploadPort`、`MissionControlPort` 和 `MissionExecutionSignalSource` 必须共享同一份航线事实。它们只模拟 DJI 层的文件上传、控制请求和原始执行信号，不处理中继协议的 KMZ 分块，也不读取用户目录。

上传端口应记录传入的受控字节和文件名供验证读取，但快照和错误信息不得暴露内容。开始和停止必须使用当前成功上传的精确文件名；没有成功上传文件时由端口按正式契约拒绝。暂停和恢复不修改文件名。每个监听器注销或关闭后不得收到新信号。

对于 `PREPARING`、`ENTER_WAYLINE`、`EXECUTING`、`PAUSED`、`COMPLETED`、`INTERRUPTED`、`IDLE`、`DISCONNECTED` 与 `UNKNOWN`，模拟器只按计划转交，不替业务模块计算任务状态或阶段。这样由真实 `MissionFlightPhase`、`MissionStateStore` 和 `WaylineMission` 证明它们的代次、阶段和终态隔离逻辑。

### 5.4 飞控

`DjiFlightPort` 对起飞、降落、返航分别维护结果队列和请求记录。成功只表示 DJI 已接受并完成该调用；飞行事实仍由遥测注入提供。并行、取消、超时、同步抛出、重复/迟到终态必须通过现有 `DjiFlightAdapter` 和 `DjiOperationCoordinator` 的公开行为被观察，模拟器不得替它们串行化或去重。

### 5.5 相机和图传设置

`DjiSettingsPort` 以完整的相机快照和图传快照为唯一可读事实。每次设置读取或写入都由计划确定：成功、拒绝、抛出、超时、重复或迟到。多字段写入的中间步骤必须能够分别失败，使真实 `SettingsExecutor` 的串行写入、失败处理和写后完整读回得到验证。

### 5.6 图传控制

`DjiStreamPort` 只记录合法 RTMP 目标与开始/停止结果，按计划提供异步终态。它不绑定本地 1935 端口、不产生视频、不调用 FFmpeg，也不把“控制成功”解释成“媒体已播放”。

## 6. 生命周期、并发与资源

1. 同一模拟器实例可同时服务一个手机中继器的所有正式模块；多台手机中继器必须创建不同实例，不得共享设备事实、计划队列、监听器或时钟任务。
2. 所有公共方法线程安全。端口回调不得在持有模拟器内部锁时执行，避免业务模块回调重入造成死锁。
3. `advanceBy` 仅交付截止时间不晚于推进后时间的事件，保持同一时刻的稳定 FIFO 顺序；`advanceUntilIdle` 必须在没有可执行事件时返回，若遇到仅等待未来时间的事件不得隐式推进时钟。
4. `close()` 幂等：立即使全部端口、监听器和待交付事件失效，释放内部引用，并使随后 `snapshot()` 明确标记 `closed=true`。关闭不得删除调用方创建的文件、端口、防火墙规则、系统设置或网络连接。
5. 每个场景结束时，验证编排器必须断言模拟器已关闭、无活动监听器、无未声明的待交付事件、无悬挂操作记录。违反任一项必须让场景失败。

## 7. 依赖与禁止项

- 仅依赖手机端已拆分的纯 Kotlin 端口模块、Kotlin/JVM 标准库和测试范围内的确定性时钟/断言工具。
- 不得依赖 `:app`、Android SDK、DJI MSDK、OkHttp Android API、`relay-gateway:transport-adapter`、桌面端源码或 Electron。
- 不得注册真实广播接收器、打开 USB、访问网络、创建临时用户文件、读取环境密钥或使用真实时间。
- 不得为了测试通过而修改生产模块状态机、增加仅供模拟器使用的生产命令，或在业务模块中加入 `if (test)` 分支。

## 8. 验证要求

实现必须先编写失败测试，再实现最小代码。测试至少覆盖：

1. 每个 `SimulationDjiPlan` 初始事实与所有端口读取的一致性。
2. 各端口的正常、拒绝、抛出、超时、重复和迟到六类结果，以及队列耗尽后的明确默认行为。
3. 航线上传、启动、暂停、恢复、停止、完成、打断、断连、任务替换、旧代次信号和 `RETURN_TO_START_POINT` 不得提前完成。
4. 起飞、降落、返航成功与真实遥测事实相互独立。
5. 相机和图传设置的完整读回、写入中途失败、无效快照与跨域字段。
6. 图传控制不伪造视频就绪。
7. 多实例隔离、订阅注销、重复关闭、回调重入、时钟稳定顺序和资源清理。
8. 固定种子生成的有界操作/注入序列：每一步断言模拟快照不变量、端口回调至多一次语义和关闭后静默。

端到端场景最终必须通过正式 `relay-test-harness` 注入本模块的端口包，且经真实 TCP/WebSocket 到达桌面端；仅对本模块做单元测试不构成跨端验证通过。

## 9. 真机边界

本模块通过只能证明：手机端业务模块面对受控、符合端口契约的 DJI/Android 结果时，可以与桌面端真实跨进程协作。它不能证明 Android 权限、USB、MSDK 注册、RC-N2/飞机连接、目标机型对 KMZ/WPML 的支持、DJI 回调的真实时序、相机/AirLink 键可用性，或实际 RTMP 推流、接收、转码和播放。这些仍需真机验收并独立记录。
