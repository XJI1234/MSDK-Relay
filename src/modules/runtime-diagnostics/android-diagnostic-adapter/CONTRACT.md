# runtime-diagnostics.android-diagnostic-adapter 二级模块契约

状态：设计并实现中
版本：0.1.0
父模块：[`../CONTRACT.md`](../CONTRACT.md)
Gradle 路径：`:runtime-diagnostics:android-diagnostic-adapter`

## 1. 唯一职责

本模块将已经由 `diagnostic-core` 脱敏的待确认事件快照写入 Android Logcat 与应用私有文件，并在应用重启后提供恢复数据。它只保存尚未收到电脑确认的事件，不是历史日志归档模块。

## 2. 规则

- 文件只能位于应用私有目录；不得使用外部共享存储、绝对路径或网络。
- 仅使用应用私有目录中的一个版本化快照文件 `diagnostics/pending-events.v1`；每次持久化通过同目录临时文件替换旧快照。文件内容是 `diagnostic-core` 有界待确认队列的完整副本，容量上限由核心传入，适配器不另行轮转或保留历史文件。
- `persistence()` 返回的端口不得在调用线程写文件、编码完整队列或调用 Logcat。它只复制不可变快照并交给本模块唯一的后台写入者；同一时刻最多一个实际文件写入，等待期间的新快照只能替换待写快照，不能无限排队。这样最终写入的是最新完整队列，而不是多个陈旧副本。
- 每行只允许写结构化的脱敏事件；后台写入失败必须被隔离并通过核心提供的失败回调增加统计，不能抛回业务模块。异常进程终止前尚未开始的诊断快照可以丢失，但不得影响 DJI、命令、中继或 UI 生命周期；已确认事件即使因陈旧快照在重启后被重复恢复，仍由电脑端去重保证安全。
- 恢复时遇到半行、损坏行或未知版本必须跳过该行并继续恢复其余合法行。
- 每次快照成功写入后，后台写入者最多向 Logcat 追加当前队列末尾的一条此前未输出事件；它不在进程恢复时重放旧事件，避免恢复时刷屏。完整待传事实以私有快照文件和电脑端确认后的无线投递为准。
- 本模块不重新执行脱敏、不过滤业务规则、不创建网关连接、不确认或删除事件。
