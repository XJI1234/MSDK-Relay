# 手机端二级模块契约模板

复制本文件到对应的二级模块目录并命名为 `CONTRACT.md`，再根据模块实际职责填写。模板本身不是实现代码，也不要求使用固定的 Kotlin 类名。

## 3. 对外接口

用调用方能理解的语义描述接口。每个入口都写清楚：

```text
入口名称(输入) -> 成功结果 | 失败结果
```

对于每个入口，补充：

- 必填字段、类型、单位、长度和取值范围；
- 调用前置条件；
- 成功后哪个状态会改变；
- 失败后状态是否改变；
- 是否允许重复调用、并发调用和取消；
- 调用方是否必须等待最终结果。

接口不得暴露 Android `Activity`、`Service`、DJI SDK 类型、WebSocket 类型、文件绝对路径或线程池类型。

## 4. 状态和生命周期

列出状态、合法转换和禁止转换。例如：

```text
IDLE -> RUNNING -> SUCCEEDED
IDLE -> RUNNING -> FAILED
RUNNING -> CANCELLED
```

说明启动、停止、重连、应用进程重启和依赖模块失效时的行为。需要特别说明“已收到请求”和“操作已由 DJI 确认成功”不是同一个状态。

## 5. 数据所有权

明确写出：

- 本模块拥有的状态、文件或缓存；
- 本模块只能读取的外部只读状态；
- 本模块不得复制、修改或持久化的外部数据；
- 状态快照是否不可变，以及时间戳或版本号如何解释。

同一份业务事实只能有一个拥有者。其他模块通过只读接口读取，不能各自维护第二份真相。

## 6. 依赖和替身

写出本模块依赖的公开接口，以及生产适配器和测试替身的替换位置：

```text
本模块 -> 公开接口
生产环境 -> Android/DJI/网络适配器
测试环境 -> 内存或记录型替身
```

模块内部可以有实现细节，但兄弟模块不得引用这些内部类或内部状态。

## 7. 错误、超时和并发

至少明确以下情况：

| 情况 | 对外结果 | 状态变化 | 是否可重试 |
| --- | --- | --- | --- |
| 前置条件不满足 | 业务拒绝 | 不开始操作 | 依条件而定 |
| 第三方操作失败 | 稳定错误 | 进入失败或恢复状态 | 依错误而定 |
| 超时 | 超时错误 | 不能假装成功 | 必须说明 |
| 取消 | 取消结果 | 清理临时资源 | 依状态而定 |
| 重复调用 | 稳定结果或明确拒绝 | 不破坏已有操作 | 必须说明 |
| 依赖断开 | 依赖不可用错误 | 清理或进入离线状态 | 恢复后说明 |

并发规则必须说明是否串行、是否只允许一个活动任务，以及旧回调如何与新任务隔离。

## 8. 测试要求

至少列出并覆盖：

- 正常输入和成功结果；
- 缺少字段、错误类型、边界值和超限值；
- 前置条件不满足；
- 第三方失败、超时、取消和异常回调；
- 重复、并发、乱序、断开和重新连接；
- 敏感信息、路径、原始文件和第三方异常不能泄露。

纯规则必须有无 Android 设备的 JVM 测试。只有真实 DJI 行为才放到设备集成测试，并在这里注明无法用 JVM 测试覆盖的部分。

## 9. 变更规则

说明哪些改动可以向后兼容，哪些改动必须先修改上级契约、电脑端契约和测试。删除入口、改变成功条件、改变单位或改变状态含义，都必须先更新契约。
