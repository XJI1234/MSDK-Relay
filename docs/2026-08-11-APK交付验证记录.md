### 注册 Key 注入与签名

DJI 开发者后台登记的 Android 包名为 `com.skycommand.relay`，与本工程 `applicationId` 一致。带该已登记 Key 的 Debug 打包已经实际成功执行。打包中发现并修复了一项阻止 Key 生效的 Manifest 合并缺陷：

1. `src/app/build.gradle.kts` 已提供 `DJI_API_KEY` 占位符；
2. 但 `android-dji-sdk-adapter` 的库 Manifest 自带同名且值为空的 `com.dji.sdk.API_KEY` 元数据；
3. 因此应用 Manifest 现在显式声明 `${DJI_API_KEY}`，并用 `tools:replace="android:value"` 使应用层配置覆盖库中的空值；
4. 修复前的 APK 解析显示 Key 长度为 `0`，该 APK 不可交付；修复后重新打包并直接解析最终 APK。

修复后的最终产物检查结果如下。为避免泄露密钥，仅记录长度和布尔结果：

```text
MANIFEST_PACKAGE=com.skycommand.relay
MANIFEST_DJI_METADATA_PRESENT=True
MANIFEST_DJI_KEY_NONEMPTY=True
MANIFEST_DJI_KEY_IS_PLACEHOLDER=False
MANIFEST_DJI_KEY_LENGTH=24
APK signature verification exit=0
APK Signature Scheme v2=True
```

这证明 APK 内的注册标识、DJI Key 注入和签名均已成立；不证明 SDK 已连接 DJI 后台或设备，因为后者必须在真机上运行后才能观察。

## 解除交付阻塞的验收顺序

1. 仅在本机进程或安全的本地密钥配置中提供已注册的 DJI Key，不写入源码或 Git：

   ```powershell
   .\gradlew.bat :app:assembleDebug -PDJI_API_KEY=<已注册密钥>
   ```

2. 用 `apkanalyzer` 核对 APK manifest 中的 DJI Key 占位符已被替换；
3. 在已连接 Android 设备上安装 APK、启动 `MainActivity`，保留 `logcat` 证明没有启动崩溃；
4. 连接遥控器、飞行器、Sky Command 和 RTMP 服务，逐项执行上节列出的六类真实链路；
5. 所有现场步骤通过后，再运行一次 `clean check` 和带密钥的 `assembleDebug`，将 APK 与命令输出一并归档。

只有完成上述五步后，才能得到“APK 已在目标环境完整运行”的证据。
